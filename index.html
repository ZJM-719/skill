01 / 10核心判断：这不是社区概念介绍，而是卖方使用指南

本期贴文的主线调整为：向卖方分析师展示如何使用 AlphaEngine Skill 社区，把研究方法转化为可持续的买方服务。

内容不再从“为什么 Skill 化值得试点”展开，而是直接回答卖方最关心的四个操作问题：

  1. 如何通过机构服务邀请点亮机构身份，并上传署名 Skill；
  2. 上传时如何在不设 Key 与设置 Key 之间选择；
  3. 买方调用后，平台如何把使用情况定时汇总并送达分析师；
  4. 这些调用反馈如何作为买方对卖方服务打分、派点的依据，并通过 Key 白名单承接获客转化。

建议保留主题「让分析师的方法，进入买方工作流」，副标题改为「机构服务邀请：机构署名、开放曝光、Key 白名单与买方调用反馈」。

叙事顺序必须是：机构邀请与署名 → 上传 Skill → 选择是否设置 Key → 买方调用 → 定时汇总送达 → 服务评价与获客转化。

公开资料可作为社区基础能力的补充：官方公开课 2026-09-14 介绍了 Skill 一键安装、直接调用和通过“/”呼出。官方 2026-09-21 介绍了与券商联合研发专业 Skill，将分析师实务经验融入 AI 工作流。本版关于机构身份、Key 双轨和调用汇总的具体操作，以用户确认及本轮上传的真实产品界面为依据。

03 / 10二、核心卖点：卖方得到的不是单一上架位置，而是一条服务链

1. 机构身份：方法有明确署名与归属

卖方通过机构服务邀请点亮机构身份后，上传的 Skill 可以带真实姓名与机构标签。两张真实界面的卡片均显示了分析师、机构标签和更新日期，说明卖方不是匿名内容供给者，而是以明确的专业身份向买方提供方法。

**对卖方的意义：**研究贡献可以被识别，机构专业形象可以随方法一起进入买方工作流。

2. 不设 Key：降低使用门槛，由平台增加社区曝光

机构上传 Skill 时不设置 Key，买方可以直接添加和使用，平台会在 Skill 社区里增加该 Skill 的曝光量。

本轮上传的无 Key 界面没有授权输入步骤，页面底部可直接“添加到我的 Skill”，并展示 Skill 使用案例。它适合承担“开放方法如何被买方看到并加入工作流”的视觉证据。

**对卖方的意义：**适合通用研究框架、公开数据核验、方法样例和希望扩大触达的成熟方法。

3. 设置 Key：用权限承接白名单服务与获客转化

机构设置 Key 后，用户如果想调用该 Skill，需要联系券商申请 Key。获得权限后，再完成授权连接并使用。

本轮上传的 Key 界面显示了 Authorization、Bearer、Key 输入框、“连接”按钮和“如何获取 Key”区域。它适合承担“Key Skill 如何形成权限门槛”的视觉证据。

**对卖方的意义：**通过 Key 和白名单确认服务对象，把社区中的方法需求转化为券商可以持续承接的客户关系。

4. 定时调用反馈：让买方使用成为卖方服务依据

平台定时汇总买方对某一 Skill 的调用情况并送达分析师，使卖方能够了解方法是否被使用、如何被使用，并据此改进方法与机构服务。

这些调用情况可以作为买方对卖方研究服务进行打分、派点的依据。传播时应直接说明这一产品价值，但不把调用量进一步换算成确定的派点比例或收入结果。

5. 开放与 Key 双轨：曝光和获客不是二选一

开放 Skill 与 Key Skill 对应不同的服务目标：前者降低体验门槛、扩大方法触达，后者设置权限、承接白名单服务。卖方可以根据方法内容、数据授权和服务深度进行选择。

**建议重点讲清“同一机构可以同时经营两类 Skill”，而不是要求所有方法只走一种分发方式。**若同一方法能否同时设置开放版与 Key 版尚未确认，不要在图文中承诺这一具体操作。

05 / 10四、卖方使用路径：从机构邀请开始

第一步：接受机构服务邀请，点亮机构身份

机构服务团队与研究所完成服务对接、机构授权和分析师身份确认。分析师上传 Skill 时，以真实姓名和机构标签呈现方法贡献。

页面需要让卖方看到：我是谁、我代表哪家机构、我上传的方法如何被署名。

第二步：上传一个可复用的方法

候选 Skill 至少说明：

  • 解决什么买方任务；
  • 需要哪些输入和数据；
  • 按什么步骤分析；
  • 以什么结构输出；
  • 哪些口径必须检查；
  • 哪些情形不适用；
  • 谁负责后续更新。

首批仍优先高频、边界清楚、可公开演示的方法，不用客户底稿，不输出评级、目标价或买卖建议。

第三步：上传时选择是否设置 Key

表 03｜第三步：上传时选择是否设置 Key

选择平台与买方路径卖方用来实现什么图文应回答的问题
不设置 Key平台增加该 Skill 在社区的曝光；买方可直接添加并调用扩大方法触达，让买方更容易开始使用“如果我希望更多买方先看到并试用，应该怎么做？”
设置 Key用户联系券商申请 Key，获得权限后连接并调用通过白名单确认服务对象，承接获客转化“如果我希望把方法用于特定客户服务，应该怎么做？”

**选择 Key 的依据是服务方式，不是方法好坏。**开放路径看触达与使用，Key 路径看申请、开通、激活和实际调用，不把两个路径的总调用量直接放在一起评价。

第四步：买方调用，平台定时汇总并送达

买方添加并调用 Skill 后，平台定时汇总该 Skill 的买方调用情况并送达分析师。分析师据此了解方法使用、开展服务复盘并持续迭代。

卖方摘要建议包含统计周期、Skill 版本、开放/Key 状态、有效调用、跨日复用、运行异常和版本更新。具体周期和字段以产品实际汇总为准，无法取得的字段标为 N/A，不以 0 替代。

第五步：用于服务评价与白名单经营

调用情况作为买方对卖方研究服务打分、派点的依据；Key 申请和白名单开通则帮助券商确认并承接服务对象。

传播收束到两条结果即可：

  • **买方为什么愿意继续用：**方法能进入真实任务，并能被反复调用。
  • **卖方为什么愿意持续上传：**方法有署名、使用有反馈、开放有曝光、Key 能承接白名单服务。

07 / 10六、可直接改写的传播文案

一份报告会被读完，一套好的研究方法还可以继续被买方调用。

AlphaEngine Skill 社区面向券商分析师提供机构服务邀请：点亮机构身份后，你可以上传带真实姓名与机构标签的 Skill，让方法以明确署名进入买方工作流。

上传时，你可以根据服务方式选择是否设置 Key。不设 Key，平台会增加该 Skill 在社区的曝光，买方可以直接添加和调用；设置 Key，用户需要联系券商申请权限，机构可以通过白名单承接服务与获客转化。

买方调用之后，平台会定时汇总并送达该 Skill 的使用情况，帮助分析师了解方法使用、改进研究服务，并作为买方对卖方服务打分、派点的依据。

让方法有署名，让使用有反馈，让研究服务在报告之外继续发生。欢迎申请 Skill 社区机构服务邀请。

英文图卡应按同一顺序压缩，不把“打分派点”简化成 earn commission，建议使用：

Usage summaries can support buy-side evaluation of sell-side research services.

如需直接对应“派点”，可使用 commission allocation evaluation，但不得写成 guaranteed commission、more clients 或 higher income。

10 / 10九、发布前只需确认操作细节，不再质疑功能主线

  1. 两张截图是否获准对外使用，分析师姓名、机构名、Skill 名称、标的信息与观点结论分别如何处理。
  2. 无 Key Skill 的“增加曝光”具体发生在哪些社区位置，文案是否需要统一为“增加曝光机会”。
  3. Key 的申请入口、券商联系人、白名单确认、授权连接、撤销与有效期说明。
  4. 调用汇总的实际周期、送达方式、统计口径和字段，尤其是有效调用与跨日复用是否可得。
  5. “作为买方打分、派点依据”的对外标准表述，避免被进一步改写为固定派点公式或收益承诺。
  6. 是否展示界面现有热度数值；默认不展示，也不比较开放与 Key 的热度。
  7. 所有截图保持真实界面，不重绘成另一套按钮或权限流程；脱敏只覆盖敏感值，不改变实际操作含义。

最终收束：这篇图文要让卖方看完就明白——先通过机构服务邀请点亮身份并上传 Skill，再根据服务目标选择开放或 Key；买方调用后，平台定时反馈使用情况，帮助卖方把方法曝光、服务评价与白名单经营连接起来。
